## Lessons learned

- The exact colocated Spec path must be used by every SDD sensor and design/evidence reference; no durable Rule change is needed because the existing SDD path contract is clear.
- External Billing access remains an explicit fail-closed integration prerequisite, not an Analytics fallback; no authority change is needed.
- Runtime access prerequisites must be registered and represented in local seed data before authenticated dashboard evidence can be meaningful; missing Billing data remains a denied state.
- Browser integration tests should name the owning page or layout and live under the corresponding module directory; no Rule authority change is needed because this correction is consistent with the existing Web test boundary.
- Date-only API values must be formatted as calendar dates through the shared date hook, using UTC parsing so the user-visible day does not shift with the browser timezone; shared hooks without a widget boundary are covered through their consumers, as explicitly required by `documentation/rules/widget-testing-rules.md`.
- Empty analytics data should remove misleading zero-only visualizations, preserve independent stock feedback, and offer one direct first-sale action; no additional product rule is needed because this implements FR-12.
- Local seed data should include representative PDV transactions and cost snapshots so the Manager dashboard can be evaluated in its populated state without changing the fail-closed behavior for establishments that have no orders.
- Current-month dashboard seed data should derive dates from the establishment timezone and stop at today, so every elapsed calendar day is represented without creating future transactions.
- Seeded daily volume should vary across elapsed current-month dates so the sales chart exercises meaningful height and order-count differences while remaining deterministic and reproducible.
- A Core use case must own the complete business action it executes; `ConsumeOrderStockUseCase` must publish its transactional stock-alert event directly instead of constructing and invoking another use case.
- A module must reuse the shared `DatetimeProvider` whenever a use case needs the current business instant; deterministic construction from explicit date data remains valid. The Provision Rule now states this distinction explicitly.
- A Core use case should expose the application action in `execute()`, keep class-owned steps in private methods, and name non-trivial intermediate shapes locally unless they are genuine shared domain contracts. The Core Rule now states this decomposition explicitly.
- Integrated review must replay the complete UI contract, not infer behavior from focused tests: retained-data failures, responsive reading order, dialog contents, persisted settings, interaction-log failure handling and REST-example parity each require current direct evidence before conclusion.
