## Lessons learned

- Product-specific Playwright route mocks should be exact or registered so broad `**/products/**` handlers can pass unrelated requests through to their intended fixtures.
- Signed order-preview facts can retain the prior accompaniment price needed for a precise reprice explanation without adding internal catalog metadata to the public preview response.
- A server-repriced cart and its token are one authoritative result; refreshing an identical line selection can race and replace the token before the user's next confirmation.
- The generic contract shared by pure domain Strategies belongs under the shared domain boundary, not the integration `interfaces` directory; the architecture checker caught this before integration was complete.
- Test Strategy behavior through consuming use cases so Core unit tests preserve the repository's use-case-only test boundary.
- Treat the full CI mutation gate as a separate contract from the Spec's selected-file mutation scope; changed files newly included in the CI hybrid threshold still need their own 70% scores.
- Re-run Complexity checks after moving production functions: baseline matching is path-sensitive, so file moves can expose violations that were previously recorded under another path.
- Keep shared providers at their existing module boundary when only one provider's behavior changes; path-only moves add churn and can invalidate an otherwise accurate Spec path contract.
- Version signed-preview facts when their canonical digest shape changes. Preserve the legacy digest for old claims that omit a new optional field, and bind the field only under the new token version.
- Keep browser screenshot output paths in test-runner options, never in an API request-body expectation.
