## Lessons learned

- FND-01 was a feature-specific baseline gap; no durable update to `documentation/prds/pdv.md`, `documentation/architecture.md` or `documentation/modules.md` was warranted beyond the approved PRD and Spec contracts.
- FND-02, FND-03, FND-07 and FND-08 were mismatches caught by existing Core, Validation, Controller Testing and Spec-conformance guidance. No update was warranted to `documentation/rules/core-package-rules.md`, `documentation/rules/validation-package-rules.md`, `documentation/rules/controllers-testing-rules.md` or `documentation/sdd.md` because the relevant contract and validation expectations were already explicit.
- FND-04 and FND-10 were stale clean-base assertions and a stale route fixture isolated to existing tests. No global testing-rule update was warranted; the test expectations and fixture were corrected and the current coverage, Playwright and test-integrity checks pass.
- FND-05, FND-12 and FND-13 were feature-local visual mismatches. `documentation/design.md` already defines the semantic colors and visible focus treatment; no broader Design update was warranted.
- FND-06's local environment issue is already addressed by `documentation/tooling.md`, which requires `DATABASE_URL` for database commands. No Tooling update was warranted.
- FND-09 and transient cases under FND-11 did not reproduce as stable product failures. No durable change to `documentation/tooling.md` or the Playwright Rules is warranted for transient resource contention or isolated timing variability.
- FND-14 showed stale visual evidence after a UI refinement. `documentation/prompts/implement-spec-prompt.md` already requires fresh captures and Evaluation reconciliation after UI changes; no durable update was warranted.
