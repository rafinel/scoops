## Lessons learned

| Snapshot facts must be built from the originating mutation transaction and published only after commit; a later read can observe a different state. | `FND-001` | Already required by the Spec and messaging/database Rule Pack; no authority change, implementation correction and focused rerun required. |
| Localized popup items do not guarantee a controlled Select's closed trigger is localized; visible trigger copy must be explicit and tested. | `FND-011` | `documentation/rules/ui-layer-rules.md` now requires pt-BR labels for every visible/accessibility state and prohibits exposing raw technical values. |
| Derived pricing errors need reconciliation when component totals change independently of the price field; inactive Combos intentionally permit non-saving prices. | `FND-012` | Clear only stale manual errors against current derived totals and keep the active-only business guard explicit in both code and consumer tests. |
| A single-choice domain field can still use Checkbox visuals when the UI contract requires them; the renderer must retain one selected canonical identifier. | `FND-013` | Keep selection ownership in the existing hook, expose accessible Checkbox state in the consuming widget, and verify replacement selection in both consumer and route tests. |
| Aggregate repository tests can be noisy when unrelated dirty-worktree suites are included; conclusion evidence should keep the feature's focused gates explicit and let PR CI validate the scoped commit. | `FND-014` | Preserve the focused cross-layer evidence and record the aggregate limitation without changing unrelated product code. |
