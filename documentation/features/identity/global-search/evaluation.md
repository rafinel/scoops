## Lessons learned

- Durable documentation dispositions: F-16 is reflected in the three affected module PRDs because it clarifies approved Operator-visible behavior. F-17 is reflected in the SDD authority and its create-spec/create-plan/implement-spec workflows, with a scoped Visual Reviewer role definition, because fresh state/viewport captures and the review handoff are reusable workflow guidance. F-15 needs no Rule, Architecture, PRD or Design change: literal substring escaping is an implementation detail already required by this Spec's matching Contract and covered by provider regression tests. F-18 needs no Tooling or Rule change because it is a one-off transient resource contention and the full suite passed when rerun alone.
